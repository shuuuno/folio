# Hallmark 최종 검토

대상은 Folio의 실제 PySide6 Windows 작업 공간이다. 사용자 요청대로 현재 세션에서 단독 검토했다. [Hallmark SKILL.md](../../.agents/skills/hallmark/SKILL.md), `references/redesign.md`, `references/gates.md`의 기준을 읽고 기존 디자인의 최종 audit에 적용했다. 테마 교체나 웹 화면 제작은 하지 않았다.

## 자동검사 적용 한계

다음 명령을 실제 실행했다.

```powershell
node .agents/skills/hallmark/scripts/sloplint.mjs paperlight --scope app --render --json
```

종료 코드 1, 출력:

```text
sloplint: no .html, .css, .jsx, .tsx, .vue, .svelte or .astro files found
```

Qt Widgets는 HTML/DOM이 없으므로 렌더러를 연결할 수 없다. 자동검사는 **지원되지 않음**이며 ‘0건 통과’가 아니다. QSS를 CSS로 위장하거나 별도 웹 모형을 검사하지 않았다. Impeccable 웹 detector·overlay도 같은 이유로 적용하지 않았다.

## 적용 가능한 게이트 검토

| 기준 | 실제 근거와 처리 |
|---|---|
| 40·41 대비 | 캔버스 위 보조 글자가 4.44:1임을 계산으로 발견해 `muted`를 짙게 수정했다. 최종 4.92:1. 입력 경계도 3.12:1로 조정했다. 주요 버튼 글자는 6.65:1 이상이다. 비활성 조작부는 별도 색과 실제 disabled 상태를 유지한다. |
| 26a 포커스 | 버튼·도구·검색·입력에 즉시 보이는 점선/실선 포커스가 있다. 파란 선택 도구의 포커스는 흰 점선이다. 폼 접근성 이름과 label buddy를 보완했다. |
| 39a 입력 안정성 | 입력 focus 테두리를 1→2px로 바꾸는 대신 padding을 1px 줄여 전체 크기를 유지한다. Qt QSS는 웹 outline과 다르다. 스핀 내부 QLineEdit에는 이중 테두리를 적용하지 않고 콤보 화살표 공간도 유지한다. |
| 34·49·73 창 크기와 잘림 | 960×640에서 문서·속성 가로 넘침이 없다. 하단 고정 적용·취소 버튼은 필드 스크롤에 따라 이동하지 않는다. 새 회귀 테스트에서 텍스트 적용까지 확인했다. 100%·125%·175% 화면에서 주요 라벨이 읽힌다. |
| 48 토큰 | UI 스타일·팔레트·아이콘의 의미 색상과 글자 크기는 `theme.py`를 공유한다. PDF 편집 내용의 잉크, 본문 표시와 문서 선택 표시는 UI 테마와 구분해 보존했다. |
| 2a·4·29·30a·38i·54·67 | 장식 그라데이션·중첩 카드·광택·이모지 아이콘·부분 이탤릭 제목·장식용 소제목·자간을 벌린 대문자 라벨을 추가하지 않았다. 기존 선 아이콘만 쓴다. |
| 46a·70·84 | 새 수치·증언·보안 주장·가짜 성공 상태·가짜 제품 그림이 없다. 전후 PNG는 실행 중인 실제 Qt 화면이며 서명 획과 입력은 검증용 합성 데이터다. |
| 10a·15·27·62 | 장식 애니메이션과 지연 포커스를 추가하지 않았다. 위젯은 기본 상태에서 보이며 스크립트 기반 등장 효과가 없다. |
| F4·F15·F16 | 한 계열 주요 버튼과 입력·선택·스크롤바 스타일을 공유한다. 저장은 파일 작업, 하단 적용은 PDF 반영으로 역할이 구분된다. 문서 자체에는 UI 색상을 적용하지 않는다. |

HTML stamp, hero, 320px 모바일 뷰포트, 웹 SEO·ARIA·브라우저 컨테이너 관련 게이트는 이 제품에 적용되지 않는다. 실제 기능을 제공하는 Windows 제목줄은 ‘홍보 페이지에 그린 가짜 OS 창’에 해당하지 않는다. 예제 PDF 안의 제목·라벨·색상은 사용자 문서 내용이므로 바꾸지 않았다.

## 최종 판단

적용 가능한 기준에서 확인한 미해결 기능 결함은 없다. 대비 14쌍과 PNG 16개 무결성 검사는 [verification.json](verification.json), 사전 문제와 수정 계획은 [audit-critique.md](audit-critique.md)를 따른다.

Impeccable 재검토 판단은 접근성 3, 성능 3, 테마 3, Windows 적합성 3, 크기 적응 4로 **16/20**이다. 성능 개선을 주장하지 않으며, 스크린리더·Windows 시스템 고대비 모드 전체 검증을 하지 않아 접근성 만점으로 평가하지 않았다. 디자인 critique는 일관성·알아보기·시각 위계를 각각 한 단계 높여 **32/40**으로 판단했다. 이는 실제 사용성 실험의 측정값이 아니다.

변경 전이 더 나았던 점은 좁은 도구막대로 확보한 문서 폭이다. 이번에는 소유자의 명시적 요청에 맞춰 읽기 쉬운 도구명과 눈에 띄는 선택·패널 위계를 택했다. 페이지 목록 접기와 읽기 모드는 그대로 사용할 수 있다. 작은 창의 입력 스크롤과 항상 보이는 적용 영역이 이 절충을 보완한다.

설치판 재빌드·배포, 실제 수동 IME 조작, 스크린리더 전 경로 시험은 하지 않았다. 도구 지원 한계나 미수행 검사를 자동 통과로 계산하지 않는다.
