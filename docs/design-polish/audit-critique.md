# Impeccable 사전 점검

방식: 단일 세션의 실제 Windows Qt 화면 및 소스 검토. 사용자의 별도 에이전트 금지 지시를 따른다. 웹 DOM 검사와 브라우저 오버레이는 PySide6 Widgets에 적용되지 않는다. iOS·Android의 터치 치수 대신 Windows 마우스·키보드, 논리 픽셀과 배율을 기준으로 해석했다.

대상: `paperlight/window.py`, `workspace.py`, `style.py`, `theme.py`, `conversion_dialog.py`, `signature.py`. 화면 근거: `01`~`08`의 `before.png`. 실제 PDF 내용의 스타일은 평가·수정 대상에서 제외한다.

## 기술 audit

네이티브 적합성: 통과. Qt 위젯, 기존 창 조작·메뉴·단축키·미저장 확인을 유지한다. 웹 장식, 랜딩 페이지, 브라우저 모양의 가짜 UI는 필요 없다.

| 영역 | 사전 점수 / 4 | 근거 |
|---|---:|---|
| 접근성 | 2 | 아이콘 조작부 이름은 있으나 본문 입력의 명시적 접근성 이름과 변환 폼 label buddy가 없다. 선택 도구의 저명도 배경도 약하다. |
| 성능 | 3 | 썸네일 지연 생성·현재 페이지 렌더링·별도 변환 프로세스 사용. 이번 평가는 프로파일링 결과가 아니다. |
| 외관과 테마 | 2 | 색상 토큰이 일부에만 적용되며 스타일·팔레트의 값이 중복된다. |
| Windows 적합성 | 3 | 실제 네이티브 창과 메뉴·키보드 동작 유지. 보조 글자와 제목의 크기 차이가 작다. |
| 창 크기 적응 | 3 | 960×640에서 기존 속성 세로 스크롤과 너비 맞춤은 작동한다. 큰 글자·새 배치의 회귀 확인이 필요하다. |
| 합계 | 13 / 20 | 우선순위는 작업 영역 구분과 글자 위계다. |

## 디자인 critique

Folio의 문서 중심 구조와 선 아이콘은 목적에 맞는다. 세로 도구·페이지 목록·중앙 PDF·조건부 속성 패널은 유지한다. 다만 상단의 큰 빈 구간과 작은 도구 라벨, 평평한 속성 패널은 첫눈에 작업 구조를 파악하기 어렵게 한다.

| Nielsen 항목 | 사전 점수 / 4 | 근거 |
|---|---:|---|
| 시스템 상태 | 3 | 변경 별표·저장 상태·미리보기·복구 상태가 있다. |
| 현실과의 대응 | 3 | 한국어와 파일·페이지·서명 표현이 익숙하다. |
| 사용자 통제 | 4 | 실행 취소·다시 실행·선택 취소·미적용 입력 보호가 있다. |
| 일관성 | 2 | 패널·대화상자·작업 버튼의 제목 및 그룹 위계가 약하다. |
| 오류 예방 | 4 | 원본 보호·검증 저장·미리보기·복구를 유지한다. |
| 알아보기 | 2 | 아이콘 아래 11px 도구명, 약한 선택 배경. |
| 숙련자 효율 | 3 | 단축키·탭 전환·검색을 제공한다. |
| 절제와 명료함 | 2 | 상단 작업이 양 끝으로 흩어지고 패널 입력은 구분 없이 이어진다. |
| 오류 회복 | 3 | 오류 안내·편집 롤백·복구 경로가 있다. |
| 도움말 | 3 | 한국어 힌트·툴팁·예제 문서가 있다. |
| 합계 | 29 / 40 | 점수는 디자인 판단이며 사용성 실험 결과가 아니다. |

인지 부하: 그룹화·시각 위계·선택 최소화 3개 항목이 약하다. 도구 5개를 없애기보다는 읽기와 편집 사이를 구분하고 선택을 명확히 한다. 초심자는 작은 도구명과 비슷한 입력 그룹에서 머뭇거릴 수 있다. 반복 사용자는 작업 버튼의 먼 이동과 좌표 입력의 좁은 너비가 불편할 수 있다.

## 우선순위와 적용 계획

1. [P2] 상단 작업 분산 (`workspace.py`): 파일·열기·변환을 왼쪽에 모으고 저장·변경 상태를 오른쪽에 유지한다. Impeccable layout/bolder.
2. [P2] 도구 선택 약함 (`window.py`, `style.py`): 아이콘 옆 한국어 라벨, 더 넓은 행, 진한 단색 선택으로 구분한다. 읽기와 편집 사이 간격을 둔다. Impeccable bolder/typeset.
3. [P2] 속성 위계 약함 (`build_inspector`): 큰 제목, 내용·서식·위치의 간격과 경계, 대비되는 패널 표면, 넓은 입력을 함께 적용한다. Impeccable polish.
4. [P2] 의미 토큰·접근성 누락 (`theme.py`, 폼): UI 팔레트와 스타일을 공유하고 편집 입력 이름·폼 buddy를 보완한다. PDF 원본의 색과 글꼴은 그대로 둔다.
5. [P3] 변환·서명 제목과 빈 화면: 공통 제목 스케일과 작업 구분을 적용한다. 기존 빈 상태를 다듬으며 새 소개·랜딩 화면을 만들지 않는다.

P0 0개, P1 0개, P2 4개, P3 1개. 질문 생략: 사용자가 모든 문제의 수정, 눈에 띄는 위계·배치·글자·표면 개선, 기존 기능 보존과 현재 세션 진행을 이미 명시했다. 단계별 승인 질문은 추가하지 않는다.

검토의 질문에 대한 결정: 강조 대상은 PDF 작업 도구와 편집 패널이다. 밝은 바탕·Pretendard·선 아이콘·파란 선택이라는 기존 정체성 안에서 강도를 높인다. 새 기능·주장·장식·애니메이션은 필요 없다.
