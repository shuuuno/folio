Python pefile을 통한 보조 정적 관찰: 실행 파일 1.67 MB, 코어 DLL 76.31 MB. EXE import DLL 9개, 코어 import DLL 32개. 코어 export에 `PXV_GetInstance`, `PXV_GetTextFromHRESULT`, COM 진입점들이 존재한다. 이는 실행 진입점과 편집 코어를 분리한 구조를 뒷받침하지만 특정 편집 알고리즘을 증명하지 않는다. `*-metadata.json`에 근거를 보관했다.

Resources.dat 내부 XML을 별도로 읽어 본 결과 문자열·대화상자 템플릿·시작 화면 템플릿·테마가 분리돼 있다. 서명 파일 불러오기, 서명/이니셜 가져오기·내보내기, 인증서 기반 서명에 서로 다른 문자열 식별자가 있다. UI에 나타날 가능성이 있는 기능 정의이며 런타임 사용 가능성이나 라이선스별 활성화 상태를 증명하지 않는다. `resource-findings.json`은 제한된 키워드 검색 결과다.

분석 한계: Ghidra와 Java가 설정되어 있지 않아 코어의 네이티브 함수 디컴파일·호출 경로·실제 실행은 확인하지 못했다. 바이너리 전체를 완전히 해독했다고 주장하지 않는다. 서명·레이아웃 구조의 관찰과 공식 동작 문서를 참고하여 자체 코드를 구현했다.

## 편집 동작 및 엔진 결정

[PDF-XChange 본문 편집 안내](https://help.pdf-xchange.com/pdfxe10c/adding-and-editing-document-text_ed.html)는 기존 base content 수정과 텍스트 추가를 구분한다. Paperlight도 보기/본문 수정/텍스트 추가/서명을 별도 작업으로 나눴다. 썸네일은 왼쪽, 문서는 가운데, 선택한 도구의 옵션은 오른쪽에 둔 것은 개인용으로 단순화한 독립 설계다.

Foxit Desktop SDK, PDF-XChange Editor SDK, Apryse는 실제 콘텐츠 편집용 후보이나 일반 앱 이용권과 별도의 SDK 계약이 필요하다. PDF-XChange의 공개 SDK 설명은 최소 US$4,995 / 50,000 배포석 조건을 제시하고 있으며 개인용 예외견적은 확인하지 않았다. Foxit·Apryse 개인용 OEM 비용은 확인 불가. [PDF-XChange SDK 비용](https://www.pdf-xchange.com/editor-sdk-more-info/editor-sdk-cost-benefit), [Foxit SDK](https://www.foxit.com/sdk/desktop/), [Apryse Windows SDK](https://docs.apryse.com/core/guides/download?tab=windows).

이 앱에는 PyMuPDF + PySide6 Widgets를 선택했다. 완전 로컬 처리, 한글 폰트 내장, 독립 실행 파일 제작이 가능하고 계정·키 활성화가 필요하지 않기 때문이다. 이는 상용 편집 엔진과 동등한 범용 편집 기능을 보장한다는 뜻은 아니다.

본문 수정 절차는 복사본 생성 → 원본/새 글꼴 글리프 확인 → 겹침·영역 검사 → 기존 텍스트만 제거 → 새 본문 삽입 → 주변 텍스트 보존/새 글자 추출 확인 → 적용이다. 기존 redaction, 링크, 겹친 본문은 안전하게 거부한다. 저장은 임시 파일 작성과 재개방 확인 이후 원자적으로 교체한다.

공식 근거: [PyMuPDF Page API](https://pymupdf.readthedocs.io/en/latest/page.html), [Font API](https://pymupdf.readthedocs.io/en/latest/font.html), [Document API](https://pymupdf.readthedocs.io/en/latest/document.html), [라이선스](https://pymupdf.readthedocs.io/en/latest/about.html#license-and-copyright), [Qt 배포](https://doc.qt.io/qtforpython-6/deployment/index.html).

## 질문별 결론

- 평가 좋은 Windows 참고 제품 선정: 답함. 점수의 표본·플랫폼 한계를 기록함.
- 참고 앱 배포 구조 및 리소스 분리: 부분 답함. 아티팩트/리소스 관찰만 확보.
- 상용 코어 본문 편집 알고리즘 전체: 미해결. native provider 부재.
- 개인 앱에서 실제 텍스트 교체·한글·서명·저장 가능 여부: 자체 구현의 합성 문서 테스트로 검증. 상용 앱과의 동일성은 주장하지 않음.
- 개인용 UI: 독립 설계. 타사 코드와 자산을 배포물에 포함하지 않음.
