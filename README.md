# Folio

실행 파일·설치판·시작 메뉴·Windows 기본 앱 표시를 Folio로 통일했습니다. 기존 Paperlight의 설정·서명·복구본과 PDF 연결 식별자는 유지합니다.

Windows에서 개인과 내부 팀이 쓰는 오프라인 PDF 뷰어·편집기입니다. 문서를 서버로 보내지 않으며 로그인이나 인터넷 연결 없이 사용할 수 있습니다.

## 실행

**설치판:** 0.11.0부터 `Folio-win-Setup.exe`를 실행한 뒤 시작 메뉴에서 Folio를 여세요. Windows 10/11 64비트용이며 관리자 권한과 Python 설치가 필요하지 않습니다.

**포터블:** `Folio-0.11.0-Portable.zip`을 풀고 폴더 안 `Folio.exe`를 실행하세요. 폴더 전체를 함께 보관해야 합니다. `시작하기.pdf`로 기능을 확인할 수 있습니다. 설치·업데이트·제거 방법은 [팀 배포 안내](docs/배포.md)를 참고하세요.

- 파일 열기 또는 PDF 드래그 앤 드롭. PDF 경로를 실행 인수로 전달할 수도 있습니다.
- 보기: 페이지 썸네일, 검색, 확대·축소, 너비 맞춤. Ctrl+휠로 확대하고 페이지 끝에서 휠을 굴리면 다음 페이지로 이동합니다.
- 글자 위를 드래그하면 같은 페이지 안의 텍스트가 선택됩니다. Ctrl+C 또는 오른쪽 클릭의 텍스트 복사로 복사합니다. 빈 곳을 드래그하면 페이지를 이동합니다. PDF의 복사 제한을 따르며, 스캔 이미지에 없는 텍스트를 OCR로 만들어 복사하지는 않습니다.
- 검색: Enter/F3로 다음 결과, Shift+F3로 이전 결과로 이동합니다. 현재/전체 결과 수를 표시하고 마지막 결과 뒤에는 처음으로 돌아갑니다. 확대해도 검색 표시가 유지됩니다.
- 본문 수정: 글자를 클릭하고 오른쪽에서 문구·글자 크기·색·영역 너비를 바꾼 뒤 **문서에 적용**을 누르세요. 한 줄/같은 서식의 텍스트 묶음 단위입니다. 입력을 잠깐 멈추면 실제 PDF 엔진으로 만든 미리보기가 나타나며, 적용 전에는 문서가 바뀌지 않습니다.
- 본문 삭제: 선택한 본문의 내용을 모두 지우면 삭제 미리보기가 나타납니다. **본문 삭제 적용** 또는 저장을 누르면 실제 PDF 문자가 제거됩니다. 실행 취소로 되돌릴 수 있습니다. 삭제는 선택한 한 줄/서식 묶음 단위입니다.
- 텍스트 추가: 문서 위에서 영역을 드래그하고 내용을 입력합니다. 한글·영문과 여러 줄을 지원합니다.
- 글꼴: 텍스트 추가·본문 수정·추가한 텍스트의 배치 편집에서 Windows 설치 글꼴을 선택합니다. 새 텍스트의 기본은 맑은 고딕이며 마지막 선택을 기억합니다. 본문은 ‘원본 글꼴 유지’, 추가 항목은 ‘내장 글꼴 유지’를 선택할 수 있습니다. 선택한 글꼴은 PDF에 전체 내장하며 임베딩 제한·보기/인쇄 전용·비트맵 전용 글꼴은 목록에서 제외합니다. 한글이 없거나 문자 매핑을 검증하지 못하면 적용하지 않습니다. 자세한 범위와 검증은 [글꼴 선택 안내](docs/design-polish/font-picker.md)를 참고하세요.
- 서명: 직접 그리기, PNG/JPG 불러오기, 마지막 서명 재사용. 문서에서 영역을 드래그하고 위치·너비·높이를 조정한 뒤 적용합니다.
- 배치 편집: 0.5.0부터 추가한 텍스트·서명을 클릭해 다시 선택합니다. 안쪽을 드래그해 이동하고 모서리 점으로 크기를 조절한 뒤 **문서에 적용**을 누르세요. 오른쪽에서 위치·크기를 숫자로 입력할 수도 있습니다. 텍스트 상자는 내용·색·글자 크기도 바꿀 수 있으며 상자 크기를 바꿔도 글자 크기는 자동으로 확대되지 않습니다.
- 선택 항목 삭제: 배치 편집의 삭제 버튼 또는 문서에 포커스가 있을 때 Delete를 누릅니다. 뒤의 원래 PDF는 유지하며 실행 취소가 가능합니다. 저장한 PDF를 다시 열어도 추가 항목을 선택할 수 있습니다.
- 다른 이름으로 저장: 기본 파일명은 `원본이름_편집.pdf`입니다. 원본을 보호하려면 이 이름을 사용하세요. 같은 경로를 직접 선택하면 저장 대화상자의 덮어쓰기 확인 후 교체합니다.
- 저장 버튼은 현재 입력 중인 내용도 적용한 뒤 저장합니다. 영역을 넘치는 등 적용할 수 없는 입력이면 저장을 중단합니다. 저장 대화상자를 취소하면 입력은 그대로 남습니다.
- 페이지·도구·선택을 바꿀 때 미적용 입력이 있으면 적용/버리기/취소를 선택합니다. 같은 본문을 다시 클릭해도 입력이 유지됩니다.
- 문서 전체 실행 취소/다시 실행: Ctrl+Z / Ctrl+Shift+Z. 텍스트 입력 칸에 포커스가 있으면 입력 내용의 실행 취소가 우선합니다.
- Ctrl+O 열기, Ctrl+S / Ctrl+Shift+S 다른 이름으로 저장, Ctrl+F 검색, Escape 선택 취소.

## 자동 업데이트 (0.11.0부터)

설치판은 시작할 때 공개 저장소 [shuuuno/folio의 GitHub Releases](https://github.com/shuuuno/folio/releases)에서 안정 버전을 확인하고 새 버전을 백그라운드로 다운로드합니다. **더보기 → 업데이트 … 설치 및 재시작**에서 적용합니다. 다운로드가 끝나면 창이 보이는 경우 재시작 여부를 안내하며, 나중에 적용할 수도 있습니다. 미저장 문서·미적용 입력은 기존 종료 확인을 거치고 취소하면 그대로 유지됩니다. 변환 중에는 재시작하지 않습니다. 오프라인·서버 오류·검증 실패 시 편집을 계속하며 메뉴에서 재시도할 수 있습니다.

문서·서명·설정·PDF 경로는 보내지 않습니다. 업데이트 확인과 패키지 다운로드에만 인터넷을 사용하며 GitHub에 일반 네트워크 요청 정보가 전달됩니다. 개발 실행과 포터블은 자동 업데이트를 하지 않습니다. 첫 공개 Release가 게시되기 전에는 업데이트를 받을 수 없습니다.

**0.10.x 이하 NSIS 설치판:** 모든 작업을 저장하고 트레이의 **완전히 종료**를 누른 뒤 Windows에서 기존 Folio/Paperlight를 제거하고 새 설치판을 한 번 설치하세요. 기존 설치 폴더의 사용자 문서는 먼저 다른 곳에 보관하세요. `%LOCALAPPDATA%\Paperlight\Paperlight`의 설정·서명·복구본은 유지합니다. 새 기본 설치 위치는 `%LOCALAPPDATA%\Folio`이며, PDF 기본 앱은 Windows 설정에서 다시 확인하세요. UserChoice/Hash는 직접 변경하지 않습니다.

## 화면 구성 (0.10.0)

0.9.1은 창 제목줄과 문서 탭을 한 줄로 통합했습니다. 별도 제품명 배너는 없애고 탭 바로 옆에 파일 추가 버튼을 둡니다. 0.9.2는 상단 왼쪽에 작은 Folio 워드마크를 한 번 표시하고 Windows UI 글자 렌더러를 FreeType으로 변경해 메뉴·탭·버튼의 거친 획을 개선했습니다. 빈 상단 영역을 드래그하면 창이 이동하고, 두 번 클릭하면 최대화/복원됩니다. 가장자리로 크기를 조절하며 오른쪽 버튼으로 최소화·최대화·닫기를 수행합니다. 닫기는 기존 트레이 설정과 미저장 확인을 따릅니다. Alt+Space 또는 상단 빈 곳의 오른쪽 클릭으로 창 메뉴를 엽니다.

0.10.0은 상단 높이·여백과 선택 표시를 줄이고 변환·서명·복구 대화상자의 글꼴·여백을 통일했습니다. 작은 창에서는 오른쪽 속성 패널을 스크롤할 수 있습니다.

상단에서 **열기·변환·저장**, 왼쪽에서 **보기·본문 수정·텍스트·서명·배치 편집**을 선택합니다. 페이지 목록은 도구막대 왼쪽 아이콘으로 접을 수 있습니다. **파일** 메뉴에는 작업 복구가, 오른쪽 위 **더보기**에는 기본 앱·트레이·종료 설정이 있습니다. 저장은 이전과 같이 다른 이름으로 저장합니다.

밝은 작업 공간, 얇은 선 아이콘, Pretendard UI 글꼴을 사용하며 최소 960×640 창에서도 편집과 페이지 탐색을 사용할 수 있습니다. 문서의 원래 글꼴·색상은 UI 테마와 별개입니다.

## 탭 · 변환 · Windows 통합

여러 PDF를 한 번에 선택하거나 앱 위에 드래그하면 각각 탭으로 열립니다. 같은 파일을 다시 열면 기존 탭을 선택합니다. 탭마다 입력 중인 문구, 페이지, 확대, 실행 취소, 복구본을 따로 유지합니다. Ctrl+Tab / Ctrl+Shift+Tab으로 이동하고 Ctrl+W로 현재 탭을 닫습니다. 탐색기에서 PDF를 추가로 열어도 실행 중인 앱으로 전달합니다.

상단 **변환**에서 파일과 결과 폴더를 선택합니다. 현재 탭의 저장 전 편집 내용을 복사해 변환할 수도 있습니다. 변환 중에도 다른 탭을 사용할 수 있습니다.

| 입력 | 결과 | 범위 |
|---|---|---|
| JPG/JPEG, PNG | PDF | 이미지 비율과 EXIF 방향 반영, 파일별 PDF |
| DOC/DOCX, PPT/PPTX | PDF | 설치된 Microsoft Office 또는 LibreOffice 필요 |
| PDF | JPG, PNG | 전체 페이지를 번호별 이미지로 결과 폴더에 저장 |
| PDF | DOCX | 편집용은 본문·그림 순서로 재구성. 표 구조·다단·원래 배치는 보장하지 않음 |
| PDF | PPTX | 가로 본문을 편집 가능한 글자 상자로 변환. 도형은 배경, 회전/세로쓰기 페이지는 이미지로 유지 |
| PDF | DOCX/PPTX 모양 보존 | 각 페이지를 이미지로 넣음. 글자는 편집 대상이 아님 |

PDF에서 Office로 변환하는 데는 Office 설치가 필요하지 않습니다. 스캔에는 OCR을 하지 않습니다. 암호화·복사 제한 PDF는 변환하지 않습니다. 96/150/300 DPI를 선택하며 아주 큰 페이지는 해상도를 낮춰야 합니다. 원본과 기존 결과를 덮어쓰지 않고 새 이름으로 저장합니다. 여러 파일 중 하나가 실패하면 해당 묶음의 결과를 게시하지 않습니다. 취소는 처리 경계에서 적용되며 Office가 처리 중인 파일은 완료될 때까지 기다릴 수 있습니다.

오른쪽 위 **더보기 → PDF 기본 앱 설정**은 Windows 기본 앱 설정을 엽니다. 거기서 Folio의 `.pdf` 연결을 직접 선택하세요. 설치판은 자동으로 후보에 등록되며 포터블은 이 메뉴를 누를 때 현재 실행 파일 위치를 등록합니다. 포터블 폴더를 옮기면 다시 등록해야 합니다. 기존 기본 앱을 강제로 변경하지 않습니다.

**더보기 → 창을 닫으면 트레이에 유지**가 켜져 있으면 X는 창만 숨기며 문서와 복구 타이머는 유지됩니다. 트레이 아이콘 또는 메뉴에서 다시 엽니다. **파일/트레이 → 완전히 종료**는 모든 탭의 미저장 작업을 확인하고 종료합니다. 트레이를 사용할 수 없는 환경에서는 일반 종료로 동작합니다. Windows 부팅 시 자동 실행은 추가하지 않았습니다.

## 자동 저장과 작업 복구

편집 중에는 약 5초 간격으로 변경된 작업의 복구본을 내 PC에 저장합니다. 원본 PDF를 덮어쓰지 않습니다. 하단의 **복구본 저장 시각**으로 마지막 완료 시점을 확인할 수 있습니다. 적용한 본문·텍스트·서명과 오른쪽 입력란의 적용 전 내용·위치·크기를 함께 보관합니다.

앱이 비정상 종료됐다면 다시 실행할 때 **이전 작업 복구** 창에서 이어갈 작업을 선택하세요. 원본이 이동·삭제돼도 복구본 자체로 열 수 있습니다. **나중에**를 누르면 그대로 보관하며 **파일 → 작업 복구**에서 다시 열 수 있습니다. 필요 없는 이전 작업은 **선택 복구본 삭제**로 지웁니다.

정상 저장이 끝나거나 종료·문서 전환 때 **저장하지 않음**을 선택하면 해당 창의 복구본을 정리합니다. 저장·종료를 취소하거나 저장에 실패하면 복구본을 유지합니다. 여러 창의 작업은 각각 보관하며 실행 중인 다른 창의 복구본은 목록에서 제외합니다. 복구 후에는 내용을 확인하고 **다른 이름으로 저장**하세요.

복구 범위는 마지막 복구본 시점까지입니다. 마지막 수초의 입력이나 첫 복구본을 만들기 전의 작업은 남지 않을 수 있고, 큰 문서 처리 중에는 간격이 길어질 수 있습니다. 종료 전 실행 취소 이력과 아직 확정되지 않은 IME 조합 문자열은 복구하지 않습니다. 하단에 **복구본 저장 실패**가 표시되면 직접 저장하세요.

복구본은 `%LOCALAPPDATA%\Paperlight\Paperlight\recovery`에만 저장되며 문서와 서명이 포함됩니다. 외부로 전송하지 않습니다. 암호화·전자서명·편집 제한으로 읽기 전용인 문서는 복구본을 생성하지 않습니다.

## 저장과 편집 범위

본문 수정은 흰색 사각형으로 가리지 않습니다. 선택한 영역의 기존 문자를 제거하고 새 PDF 본문 텍스트를 넣습니다. 글꼴을 재사용할 수 없거나 새 글자가 없는 부분 내장 글꼴이면 Windows 맑은 고딕으로 대체하며 상태 표시줄에 알립니다. 긴 문장은 영역 안에서 글자 크기를 줄이되 너무 작아지면 적용을 거부합니다. Word처럼 문서 전체를 재배치하지는 않습니다.

주변 글자가 영향을 받거나 겹치면 전체 변경을 취소합니다. 링크가 걸린 본문, 처리 전 먹칠 표시가 있는 페이지, 회전·세로쓰기 텍스트는 본문 수정 대상에서 제외합니다. 페이지 자체가 회전한 문서는 지원합니다. 이미지·윤곽선으로 그린 글자는 본문 선택 대상이 아니며 텍스트 추가와 서명은 가능합니다.

배치 편집은 Paperlight 0.5.0부터 추가한 항목에 적용됩니다. 원래 PDF에 있던 이미지나 이전 버전에서 추가한 서명을 임의로 이동·삭제하지 않습니다. 재편집에 필요한 정보는 PDF 내부에 함께 저장되므로 별도 프로젝트 파일은 필요하지 않습니다. 다른 프로그램으로 재작성하거나 PDF로 인쇄하면 이 정보가 사라져 재선택할 수 없을 수 있습니다. 서명은 원래 가로세로 비율을 유지합니다.

본문 수정·삭제 시 주변 문자의 내용뿐 아니라 위치·간격도 검사합니다. 일부 복잡한 PDF는 엔진의 본문 제거 과정에서 주변 자간이 바뀔 수 있어 수정을 취소하고 안내합니다. 이런 페이지에는 텍스트 추가를 사용할 수 있습니다. 내장 글꼴은 새 문자의 표시 가능 여부와 재삽입 후 문자 매핑을 확인한 다음 재사용합니다.

암호화·전자서명 필드·편집 제한 문서는 읽기 전용입니다. OCR와 인증서 전자서명은 제공하지 않습니다. 서명은 이미지이며 `%LOCALAPPDATA%\Paperlight\Paperlight\signature.png`에 마지막 한 개를 보관합니다. 이 파일을 지우면 보관한 서명이 삭제됩니다.

저장은 같은 폴더의 임시 PDF로 먼저 쓰고 재개방하여 페이지 수·텍스트를 비교한 다음 목적지 파일을 원자적으로 교체합니다. 저장 오류가 발생하면 기존 목적지는 유지합니다. 실행 취소는 최대 20회이며 이력의 압축된 PDF 합계가 약 96 MiB를 넘으면 오래된 항목부터 줄입니다. 종료 후에는 실행 취소 이력이 남지 않습니다.

## 개발 및 검증

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe -m paperlight
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe scripts\build.py
```

`paperlight/document.py`는 트랜잭션·본문 교체·저장을, `window.py`는 Qt Widgets 화면과 좌표 변환을 담당합니다. `signature.py`는 손그림·서명 재사용을 담당합니다. `updates.py`는 설치판의 업데이트만 담당하며 문서 처리는 로컬에서 수행합니다. 큰 문서는 현재 페이지와 보이는 썸네일만 렌더링하지만 편집 이력은 PDF 복사본을 보관하므로 큰 스캔본을 많이 수정하면 메모리 사용량이 늘 수 있습니다.

### 버전 올리기 · 빌드 · pack · 게시

빌드 PC에는 Python 3.13 x64와 .NET 10 SDK, 앱과 같은 버전의 `vpk`가 필요합니다. 일반 사용자의 PC에는 필요하지 않습니다. [Velopack Python 공식 안내](https://docs.velopack.io/getting-started/python)에 맞춰 PyInstaller `--onedir`로 빌드합니다.

```powershell
dotnet tool install --global vpk --version 1.2.161
.\.venv\Scripts\python.exe scripts\release.py --bump 0.11.1
# 변경 검토, 테스트, 커밋 후 깨끗한 작업 트리에서
.\.venv\Scripts\python.exe scripts\release.py
# 공개 전 전체 이력 검사. 발견 시 공개하지 말고 검토 결과 보고
git fetch --all --tags
.\.venv\Scripts\python.exe scripts\scan_publication.py --gitleaks C:\도구\gitleaks.exe
# 사용자에게 main 반영·푸시와 Release 게시 승인을 받은 뒤에만
.\.venv\Scripts\python.exe scripts\release.py --publish
```

기본 명령은 로컬 빌드·pack만 합니다. `release/<버전>/`에 `Folio-win-Setup.exe`, `Folio-<버전>-full.nupkg`, `releases.win.json`, 포터블·소스 ZIP, 해시·커밋 정보를 만듭니다. `--publish`는 현재 커밋과 원격 main, 저장소 공개 상태, 배포물 해시를 확인하고 `gh release`로 자산을 전부 올린 후 공개합니다. 같은 버전의 태그/Release를 덮어쓰지 않습니다. 실패해 draft가 남으면 검토 후 정리하고 다시 게시하세요. Setup EXE와 업데이트 피드를 함께 게시해야 자동 업데이트가 작동합니다.

SDK가 없는 빌드 PC에서는 공식 `vpk.1.2.161.nupkg`를 압축 해제한 뒤 설치된 .NET 10 런타임으로 `--vpk <압축해제경로>\tools\net10.0\any\vpk.dll`을 지정할 수도 있습니다. 스캐너 보고서는 비밀값을 가리고 `evidence/publication-scan/`에 보관합니다. 개인정보 자동 검사는 이메일·휴대폰·주민번호 형식 및 PDF 텍스트를 대상으로 하며 이미지 속 개인정보 등 수동 검토를 대신하지 않습니다.

`research/조사와-설계.md`에 참고 제품 비교, REA 근거, 분석 한계를 기록했습니다. `assets/`에는 합성 예제와 아이콘이 있습니다. 로컬 검증 결과인 `evidence/`는 Git에서 제외합니다. 실제 사용자 문서는 테스트에 사용하지 않았습니다.

0.4.0은 공개 PDF 3종 148페이지의 무편집 저장·재개방과 한글 본문, 계약서 부록, 이미지 스캔에 대한 편집을 검사했습니다. 출처·해시는 `research/corpus-sources.json`, 재현 스크립트는 `scripts/check_compatibility.py`입니다. 원본 PDF는 별도로 `research/corpus/`에 두며 앱에 포함하지 않습니다. 검증 범위와 제한은 [검증 문서](docs/검증.md)에 있습니다. Windows IME 및 탐색기·기본 파일 대화상자의 실제 외부 조작은 도구 연결 문제로 확인하지 못했으며 Qt 이벤트·콜백 시험과 구분합니다.

0.5.0은 배치 편집, 저장 후 재선택, 겹친 서명의 개별 삭제, 회전 페이지의 드래그, 실행 취소 및 기존 본문과 추가 항목의 독립 보존을 추가 검증했습니다. 공개 계약서·스캔본에 넣은 항목을 이동하고 저장·재개방한 뒤 삭제했을 때 원래 화면이 복원되는지도 확인했습니다. 검증 스크립트와 테스트를 소스에 포함합니다.

0.6.0은 자동 복구본과 적용 전 입력 복원을 추가했습니다. 검증용 프로세스를 실제로 강제 종료한 뒤 복구 안내에서 되살리고, 객체를 재편집해 저장·재개방하는 흐름을 확인했습니다. 0.7.0은 현재 사용자용 설치·제거, 시작 메뉴, 버전 정보와 Git 기반 소스/배포 패키지를 추가했습니다.

텍스트 복사는 PDF의 추출 순서를 사용하므로 복잡한 다단 문서에서는 순서가 기대와 다를 수 있습니다. 페이지를 넘기면 선택은 해제됩니다. 검색 결과 수는 검색어를 실행할 때 문서 전체를 확인하므로 매우 큰 문서는 잠시 기다릴 수 있습니다.

## 사용한 구성요소

PyMuPDF / MuPDF(AGPL 또는 상용 계약), PySide6 / Qt(LGPL/GPL/상용), PyInstaller를 사용합니다. 개인 및 같은 조직 내부 사용을 위해 준비했습니다. 외부 배포·서비스로 넓히기 전의 라이선스 범위는 [구성요소 고지](THIRD_PARTY_NOTICES.md)를 확인하세요. 포터블 폴더의 `licenses/`에 패키지에 포함된 라이선스 문서를 함께 둡니다. 상용 PDF 편집기의 코드·아이콘·UI 리소스를 앱에 복사하지 않았습니다.
